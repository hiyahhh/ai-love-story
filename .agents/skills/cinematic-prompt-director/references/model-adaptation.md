# Model adaptation

Keep a portable directing contract separate from target-specific prompt/settings. Change the translation when the target changes; preserve accepted story, identity, space and emotional intent.

Use current official documentation, connected tool schemas or the user's confirmed interface. Record source/version/check date when available. Never infer features from another variant, marketing name or old tutorial. Unknown is neither supported nor unsupported. If verification is unavailable, finish a portable package and mark material unknowns.

Check only relevant features: input mode, reference type/count/binding, duration, aspect ratio, resolution, native sound/dialogue, multi-shot cuts, start/end frames, camera controls, negative fields and seeds. Capabilities and prices may differ between interfaces for the same model.

| Target condition | Translation |
| --- | --- |
| No target | Clean descriptive prompt, neutral asset IDs, attachment prerequisites |
| Bound reference interface | Actual handles mapped back to stable project IDs |
| Single-image image-to-video | Selected opening image plus concise motion; do not imply independent identity bindings |
| Text-only | Compact visual anchors; disclose lack of image-reference binding |
| Multi-reference support unknown | Reference-ready brief; no invented tags or guaranteed identity lock |
| Multi-shot unavailable/unknown | Separate shot prompts and edit timeline |
| Duration too short | Split at coherent action boundaries; preserve end/start state |
| Audio unavailable/unknown | Visual prompt plus separate sound/edit direction |
| Negative field supported | Small relevant constraints; no contradictory boilerplate |
| Optical/time device unsupported | Preserve intent through feasible coverage or editing; label approximation |

Record a target profile when adapting:

- Model, version and interface; evidence source/date.
- Relevant capabilities: each verified, user-supplied or unknown.
- Actual settings, separate from cinematic prose.
- Stable asset ID → actual input mapping and readiness.
- Unsupported requests → proposed alternatives.
- Verified estimate and unit only if spending is requested.

Do not invent API fields, upload handles, credentials or prices. Keep settings commentary outside a clean copy-paste prompt. Exact timing and optical behavior remain output acceptance criteria, not promises.
